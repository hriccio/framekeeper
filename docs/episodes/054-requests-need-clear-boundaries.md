# Requests Need Clear Boundaries

## Metadata

- YouTube channel: `@umoutrohenrique`
- Status: refined

---

## Core idea

A request should stay bounded enough to review, refine, and implement.

## What I said

The loop works better when the request has a clear boundary. Otherwise it
becomes hard to know what was actually being asked for or whether the build
matched it.

## Key points

- requests need a boundary
- the boundary keeps review honest
- implementation should not redefine the request
